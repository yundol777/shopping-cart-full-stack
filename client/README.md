# 요구사항 정리

## API 호출

- API를 호출하여 장바구니 상품 데이터를 불러온다.
  - 200: 받아온 데이터 기반으로 클라이언트 상태 구성 및 출력
  - 204: 장바구니/상품 없음 분기 처리.

- 성공 시, 장바구니 화면이 출력된다.
- 로딩 시, 스피너 로딩 화면이 출력된다.
- 상품 데이터가 없을 시, 상품 없음 화면이 출력된다.
- 에러 시, 상품 없음 화면이 출력되고 에러 메세지가 토스트 UI로 출력된다.

## 장바구니

- 장바구니 상품의 수량이 출력된다.
- 장바구니 상품 리스트가 출력된다.
- 장바구니 상품의 주문 금액, 배송비, 총 결제 금액이 출력된다.

- 선택 버튼
  - 기본값으로 전체가 선택된다.
  - 새로고침을 해도 선택 여부는 유지된다.
  - 선택 여부에 따라 주문 금액이 동적으로 변경된다.
  - 하나라도 선택이 되어있지 않다면 주문 확인 버튼이 비활성화된다.
  - 전체 선택 버튼을 눌렀을 때,
    - 모든 상품이 선택되어 있었다면, 전체가 취소된다.
    - 일부 상품이 선택되어 있었다면, 전체가 선택된다.
    - 모든 상품이 취소되어 있었다면, 전체가 선택된다.
  - 상품 선택 버튼을 눌렀을 때,
    - 상품이 선택되어 있었다면, 상품이 취소된다.
    - 상품이 취소되어 있었다면, 상품이 선택된다.

- 수량 버튼
  - 감소 버튼을 누르면, 수량이 1씩 줄어든다.
  - 증가 버튼을 누르면, 수량이 1씩 늘어난다.
  - 수량의 범위는 1~99까지이다.
  - 수량이 변경될 때마다, api가 호출된다.

- 삭제 버튼
  - 삭제 버튼을 누르면, 상품이 삭제된다.
  - 삭제 버튼을 누르면, api가 호출된다.

## 주문

- 배송비
  - 결제 금액이 10만원 이상일 경우 배송비는 무료이다.
  - 상품 선택/해제 시 결제 금액을 동적으로 변경한다.

- 주문 확인 버튼
  - 상품이 선택되지 않으면, 주문 확인 버튼이 비활성화 된다.
  - 주문 확인 버튼을 누르면, 주문 확인 페이지로 이동한다.

# 주문 확인 페이지

- 상품 개수, 상품 수량을 출력한다.
- 총 결제 금액을 출력한다.

## 테스트

### 훅 테스트

- 삭제 성공 시 선택 해제 상태에서 삭제된 상품 id를 제거한다.

### 도메인 테스트

- 장바구니 상품 수량은 최소 수량보다 작으면 유효하지 않다.
- 장바구니 상품 수량은 최소 수량이면 유효하다.
- 장바구니 상품 수량은 최대 수량이면 유효하다.
- 장바구니 상품 수량은 최대 수량보다 크면 유효하지 않다.
- 주문 금액이 0원이면 배송비를 부과하지 않는다.
- 무료 배송 기준 미만이면 기본 배송비를 부과한다.
- 무료 배송 기준과 정확히 같으면 배송비를 부과하지 않는다.
- 무료 배송 기준 이상이면 배송비를 부과하지 않는다.
- 무료 배송 기준 금액을 반환한다.

### 장바구니 화면 테스트

(조회)

- 로딩 중이면 로딩 화면을 보여준다.
- 조회 성공 시 상품 목록을 보여준다.
- 상품이 없으면 빈 장바구니 화면을 보여준다.
- 조회 실패 시 에러 화면을 보여준다.

(상품 선택)

- 전체 선택과 전체 해제를 할 수 있다.
- 개별 상품을 선택하고 해제할 수 있다.
- 선택 해제 상태는 새로고침 후에도 유지된다.

(금액 계산)

- 선택된 상품 기준으로 주문 금액을 계산한다.
- 주문 금액이 무료배송 기준 이상이면 배송비가 0원이다.
- 선택된 상품이 없으면 주문 확인 버튼이 비활성화된다.

(수량 변경)

- - 버튼을 누르면 수량과 금액이 증가한다.
- 요청 중에는 수정 중 오버레이를 보여준다.
- 실패하면 에러 메시지를 보여주고 기존 상태를 유지한다.

(상품 삭제)

- 삭제 성공 시 상품이 화면에서 사라지고 총 금액을 다시 계산한다.
- 삭제 실패 시 에러 메시지를 보여주고 상품을 유지한다.
- 모든 상품을 삭제하면 빈 장바구니 화면을 보여준다.

(주문 확인)

- 주문 확인 버튼을 누르면 주문 확인 페이지로 이동한다.
